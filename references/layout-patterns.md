# 按用户任务选网页版式

用在从零建站的新页面和已有站的整体改版。已有品牌和组件先对照当前界面。用户只说“做高级点”时，先找目前需要看懂、比较、填写或处理的那一步。选择版式随[网站从讨论到交付](project-workflow.md)走到审图，用户看到实际稿后再定开发方案。

## 先找要处理的事和相近的网页

1. 写清「使用者与设备｜来这里做的事｜要读到的证据｜下一步动作｜结果」。同一网站里，首页介绍服务、案例页证明能做、咨询页负责接住需求，可以各自采用不同版式。
2. 看已有品牌、真实项目资料和可用素材。给关键页找一个任务相近的公开网页，再找能补齐一处难点的原作者案例或设计规范。比如官网首屏参考产品证据怎么摆，表单另外参考返回修改。下面的例子可以作起点，环境能访问网页时主动核对具体段落与动作。外网页无法访问时用可读的现有资料，并记录依据。
3. 记下一个要迁移的关系，例如「主按钮靠着项目成果，访客看懂后就能问相似项目」。从自己的文字、照片和组件重新排。需要知道切换、提交或窄屏表现时实际打开核对，把静态观察和已操作的结果分别标明。[从参考提取设计规则](ui-reference.md)

## 八种版式怎么选

以下手机排法是迁移建议。用本项目的内容、角色和设备验证。

| 页面与用户任务 | 桌面构图与行动 | 手机重排与易出错的地方 | 参考从哪里学 |
| --- | --- | --- | --- |
| **官网首页，先看懂服务再联系** | 文案和一个主动作放同一组，对侧放一张产品实拍或案例图。下一屏补可信证据、服务方向和可深入的入口。 | 先露出业务、动作与关键证据，再安排其他说明。用最长的业务名称检查断行，也看图会不会挡住路径。 | Stripe Connect 的业务说明和开始或联系入口后紧接产品示意。借这层顺序，给自己的业务选一个主要动作。[Stripe Connect](https://stripe.com/connect) |
| **单品页，理解一个产品再选型号** | 让一个实物或产品界面主导首屏，说明与行动紧邻。后续每段讲一个能力，再给适合进一步比较的人入口。 | 从产品页真正能访问比较和购买或预约入口。图按设备裁切，正文可先读，视频和装饰按表现再加载。 | MacBook Air 页先展示产品实物与购买入口，下方给亮点和型号比较。借内容顺序和产品证据。[Apple MacBook Air](https://www.apple.com/macbook-air/) |
| **目录，浏览案例、课程或商品** | 有代表作品时给它不同于普通条目的位置。其余统一标题、关键信息和链接。项目多到需要找时，再加分类或搜索。横向比较固定属性可用对齐列表。 | 首项仍给出可判断的标题和摘要。需要筛选时把当前条件放在结果旁，返回后恢复原条件和项目位置。 | Stripe 把客户案例组织为可进入的条目，USWDS Collection 给出标题、摘要和元信息的排法。[Stripe 客户案例](https://stripe.com/customers) · [USWDS Collection](https://designsystem.digital.gov/components/collection/) |
| **方案对比，选套餐、课程或配置** | 先给人易懂的适用对象和真实差异，再把同单位、周期和范围排齐。一张清楚的对照表适用于逐项比较。 | 两三项先试逐项叠放并保持属性顺序。确需横向比较的表格把滚动留在表格区域，确保行列标题清楚且正文能重排。 | Shopify 价格页有各方案的短说明和汇总功能对比。用同样的分层讲清自己的适用对象及条件。[Shopify Pricing](https://www.shopify.com/pricing) |
| **教程或长文，跟着读到结果** | 一栏正文给合适行宽，章节标题、示例和段落形成节奏。内容够长时用侧边目录和明确的下一章链接。 | 目录放在可找到的位置，标题锚点可直开。试较长标题、文字放大和返回阅读位置，重要示例保持可读。 | web.dev 的课程把文章分模块，章节内把解释和示例放在一起。借章节顺序和续读入口。[Learn CSS](https://web.dev/learn/css) · [Grid 章节](https://web.dev/learn/css/grid) |
| **咨询、报名或设置，填写后拿到明确结果** | 一组任务放一列，字段标签、提示和错误在近处。较长或有条件分支时，按用户实际要做的决定分步，末尾可核对和返回修改。 | 验软键盘、错误定位、返回保留输入、真实结果。短表单优先试一页。查询、生成摘要和实际送达各用准确文案。 | GOV.UK 用明确的问题组织长表单，并在提交前的核对页提供修改入口。[问题页](https://design-system.service.gov.uk/patterns/question-pages/) · [核对答案](https://design-system.service.gov.uk/patterns/check-answers/) |
| **工作台或审核队列，找到对象并接着处理** | 让侧栏、页头、筛选和主表对齐。记录多时用稳定表格，标题、当前范围和高频动作可见。用详情抽屉或独立页承接下一步。 | 常见任务优先展示对象、状态和操作，次字段可展开。实际从筛选走到详情、后退和下一条，核对角色范围与返回位置。 | Linear 的改版复盘解释导航层级与对齐取舍。Carbon 的数据表规范给出行、标题、工具栏和状态。[Linear 设计复盘](https://linear.app/now/how-we-redesigned-the-linear-ui) · [Carbon 数据表](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) |
| **专题或案例故事，按事件或过程理解内容** | 章节按明确的事件、阶段或因果展开，每段给一项对应证据。需要边读边看的时候，可让一块说明图跟着阅读步骤变化。 | 保留原生滚动，让文字和图都能按顺序读。直接开某一段、往回滚、开启减少动效时，核对内容与证据停在同一阶段。 | The Pudding 展示滚动步骤如何触发图形。把有因果关系的材料才排成这种叙事。[The Pudding Scrollama](https://pudding.cool/process/introducing-scrollama/) · [动效选择](motion.md) |

## 用同一份内容比较并定一版

比如校园摄影工作室只整理好两组授权作品，访客主要想看是否能拍自己的活动，又想快速咨询。

- **作品先行。** 首屏左边写拍摄对象和联系入口，右边放一组能代表业务的实拍。往下给作品背景和另一组案例。窄屏按「这家拍什么 → 看一组作品 → 告诉他们需求」组织。适合内容少、辨认风格后就要开始联系的人。
- **目录先行。** 首屏用简短业务说明后进入对齐的作品条目，按照活动类型、成片用途等真实差别给入口。在手机同一屏控制条目的摘要长度，进详情再咨询。只有相当一部分访客要先分别比较类型，而且作品足够展示这些差异时，才有明显收益。
- 上例优先做作品先行，再把目录留给下一屏。把相同的照片、中文标题和按钮放进两版，在桌面、手机上各让人找一次作品并点到咨询。首选用易读性、结果路径和已有素材来解释。已确定的方向可以直接试排一版。包内样站可用来练习从作品进入咨询，检查预填和摘要。[微光工作室样站](../assets/site-starter/index.html) · [咨询页](../assets/site-starter/inquiry.html)

## 把决定写进 UI 稿

每种新用的页面版式，给出实际可看的桌面与手机稿。说明内容顺序、主操作、图像的取景、正文行宽、中文标题与小字、按钮/链接规则、关键状态和互动触发。多页统一这些共同规则，加入真正适合该页的变化。用了代表性素材后，试一次较长中文、只有文字时的结构、手机与桌面之间的空间变化和内容放大。响应式调整跟着内容的断行、对齐和可点性决定。按适用范围检查约 320 CSS 像素宽时普通内容的重排，确实需要两维布局的内容按规范处理。[W3C 重排说明](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

交稿前自己做一次「看懂首页 → 选中对象 → 到结果 → 返回或重试」的顺序检查，指出稿上哪里证据不足、主要动作挤出视口或焦点和状态模糊。可交互原型用实际入口点一遍。设计图能说明排法和预期，真正的内容传递、错误恢复、动效和性能在开发后实测。让用户确认最重要的视觉决定与观感目标，再用同一份内容验证开发稿。[审图办法](ui-design-practice.md#让设计稿经得起评审) · [浏览器验收](delivery.md)
