# 从设计案例提取自己网站的 UI 规则

[VoltAgent/awesome-design-md](https://github.com/VoltAgent/awesome-design-md) 收录了对公开网站的设计分析。用它查具体的字体层级、色彩分工、组件和响应式处理。它是观察资料；商标、页面截图、商业字体与品牌图形的使用权另行核对。

## 选与当前任务相似的界面

## 让下一页接得上这次设计

从上表挑一个与用户任务相近的例子，用本项目的内容、字体和控件做出代表页。已有认可的设计稿时，按同尺寸对照标题、主操作位置与窄屏顺序，记录一处偏差及修正；只有业务想法时，先看真实内容能否说明主操作。项目已有 `DESIGN.md` 或组件规范就增补原处。需要研究新案例、核对原文或用户要求看出处时，再打开作者条目。

多页站或团队要反复接手时，把选定的关系写成项目自己的 `DESIGN.md`。例如案例页用实心按钮承接咨询，辅助阅读入口用文字链接；到咨询页，同一个按钮样式承接生成摘要。写清共享的 CSS 变量或控件、页面可以不同的地方，以及怎样用中文长标题、键盘或触屏验证。可直接对照[微光工作室的 DESIGN.md](../assets/site-starter/DESIGN.md)与它链接的两页实现。改一个按钮时，沿用现有规范就够了。

## 从参考到实现

1. 写一句“我借这个例子解决什么”。同一块界面优先选一个主参考，再找与它最可能冲突的要求，例如按钮辨识度与星空亮度、后台密度与触控面积。
2. 把视觉决定落到项目已有设计令牌或组件。可用这个最小记录：**业务任务｜参考条目与观察点｜沿用的品牌要素｜本次规则｜例外｜检验动作**。多页或团队需要复用时更新项目已有设计说明；小修直接改共享样式即可。
3. 用真实内容拼出一条纵向样例，包括正常、焦点、处理中、错误和小屏。比如把“高级表单”落实为稳定的输入面板、清晰的字段标签、错误就地定位；边缘流光和 3D 倾斜只出现在适合展示的表面，打字时停稳。给键盘、触屏各留可用反馈。
4. 同尺寸看静态截图，再走任务。官网测试访客能否辨认主要业务并找到咨询；后台测试能否认出待办、保存状态并返回原列表。动效参考另按 [运动验收](motion.md)；流程中反复输入、找不到记录或怕丢内容，转 [便利性决策](convenience.md)。

### 小例子：后台长文编辑

编辑区上方保留文章标题，右侧紧邻“提交审核”显示“正在存草稿”或“本机已存 14:32”。草稿动作采用次级按钮；提交后显示服务端回执和下一步。窄屏允许按钮换行，打开系统键盘仍看得到错误字段。验收时让人关页重进，问“刚才保存到了哪里？内容已经发出去了吗？”回答不清就调整状态文案与位置。
