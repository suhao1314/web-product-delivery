# 带新手发布第一个网站

本机预览、给别人试用的地址、顾客公开访问的正式地址，分别记录。把地址发给一个新浏览器会话，确认它能看到哪一版。文件双击能开，只能说明这台电脑上的文件能读。

## 部署前把目录认清

纯 HTML 样站选择**直接包含** `index.html`、`inquiry.html`、样式和脚本的文件夹。已有框架项目从实际脚本构建，打开构建出的首页再确认应上传的目录。有后台的站要额外运行服务器、配置私密变量与数据存储；在测试环境验证“前端提交、后台读回”后，再发布对应服务。上传静态页面只能提供文件访问。

在用户项目中替换虚构店名、案例与联系入口，确定谁能修改源码、使用托管账号和续费域名。只上传对公众开放的成品，另外保留上一版和恢复办法。用户只要求本地练习时，给他本地入口即可。

## 一条具体的静态发布示范

已有托管的客户沿用现有发布方式。下面是**用户已选 Cloudflare Pages 并授权在自己的账号上公开一个静态演示**时可走的路径。选择平台前核对当前计划、受众访问情况和地区要求。直接上传的项目如要切换为 Git 自动部署，官方要求另建项目，这项选择留到建项前说明。[官方直接上传说明](https://developers.cloudflare.com/pages/get-started/direct-upload/)

1. 登录自己的 Cloudflare 控制台，进入 **Workers & Pages**，选 **Create application**，找到 Pages 的 **Get started → Drag and drop your files**。AI 准备好上一步核对过的文件夹。本人登录或验证的步骤由账号主人在平台完成。
2. 填项目名，拖入成品目录。点 **Deploy site** 会产生公开地址。若只是给少数同事试用，先核对预览的访问范围，涉及内部资料就选带访问控制的环境。首次部署就可能公开内容。拿到平台给出的实际 HTTPS 地址后，用新会话打开首页、直接打开咨询页、刷新、返回；在手机上试真实入口。记录版本和结果。
3. 有自己的域名时，先验证托管地址，再到项目 **Custom domains → Set up a domain** 填要绑定的域名。按平台为该域名给出的配置核对 DNS 和证书。原站已有流量时，记录原设置和旧站恢复方式，切换前核对目标和授权。完成后从正式域名重走同一任务。[自定义域名文档](https://developers.cloudflare.com/pages/configuration/custom-domains/)
4. 更新时可在已有项目新建一次预览部署，实测后再发布生产版本。若新版本有问题，在 **Deployments** 选择之前成功的生产部署，执行回滚，再打开正式地址确认旧行为恢复。首发若没有上一版，准备好可重新部署的已验收文件，原有域名保留原指向。数据变更的恢复单独验证。[官方回滚说明](https://developers.cloudflare.com/pages/configuration/rollbacks/)

## 看见什么算交付

| 现象 | AI 现在怎么排查 | 给用户看的证据 |
| --- | --- | --- |
| 地址能开，还是旧文案 | 核对发布的文件夹和部署版本，用新会话访问平台地址与正式域名。 | 两个地址的标题、版本与时间；说明实际切换到了哪里。 |
| 首页正常，直接打开第二页 404 | 请求实际文件或路由，核对大小写、站点子路径及框架路由回退。 | 复制第二页地址到空白会话，打开并刷新仍是正确页面。 |
| 表单显示成功，负责人没收到 | 识别它承诺的是生成摘要、跳到联系渠道，还是服务端收件。逐段核对真实承接处，用获准的测试内容验证。 | 摘要、送达或后台记录分别写实际达到的状态。 |

把仓库位置、启动方式、正式地址、域名与托管的负责人、恢复入口交给项目主人。让他提一次小更新，例如改课程标题，在预览看过后发布、再从正式网址读回。一周后问一个具体问题：第一次来的访客能自己找到目标并办完吗？若不能，记下卡住的那一步，作为下一次改动的起点。
