# 从一句想法做出第一屏

这是一堂能边看边做的网页入门练习。我们用虚构的「青禾自习室」预约页：学生打开网页，想知道今天哪间自习室还有空位，并预约一个时段。示例里的校区、时间和余位都是演示数据。

## 先把想法变成一个动作

先别挑颜色。把目标说成：「周三午休，学生用手机找一间 14:00 还有座位的自习室，并看懂怎样预约。」这句话交代了谁、何时、用什么设备、要办成什么事。若说不出成功的动作，先缩小目标；「做个好看的自习室网站」还不能指导页面。

**AI 来做：**把你的想法改写成一句可检查的任务，再列出完成它必需的信息和一个主要动作。缺少会改变页面的事实就标“待确认”，不替你编造；本练习为演示方便，使用「桂园校区、周三、14:00、明德楼余 2 位、知行楼余 7 位」这批虚构数据。

**你来试：**读完这句任务，回答：「我做完哪一步，才算这页有用？」若答案是“看到适合的时段并能开始预约”，第一屏就该让人比较时段和余位；团队介绍、校园风景和登录入口暂时不抢位置。

**过关产物：**一条任务句、一份演示或已核实的数据、一个可观察的成功动作。可对照[按访客决定推导页面](pages.md)和[按用户任务走查](journey.md)。

## 画手机文字线框

先用文字方框排内容。下面模拟约 390 像素宽的网页视口，框内从网站自己的导航开始，到访客下一步能点的入口结束。

```text
┌────────── 青禾自习室 ────────────┐
│ 桂园校区 · 周三                     │
│ 今天 14:00，哪里还有座位？          │
│                                    │
│ 明德楼  ·  14:00–16:00             │
│ 余 2 位                    [看时段] │
│ ──────────────────────────────── │
│ 知行楼  ·  14:00–16:00             │
│ 余 7 位                    [看时段] │
│                                    │
│ 选中时段后，下一步查看预约规则      │
└──────────────────────────────────┘
```

示例文案直接告诉学生校区、日期、时间和余位；“看时段”只表示进入选择，不假装已经预约成功。两个地点放在相同位置，方便比较。主标题缩成“自习室预约”会少掉当天的任务；加“全校最佳学习体验”则没有帮助学生做决定的证据。

**AI 来做：**用同一批数据画两张文字线框，只调整信息怎么组织；保留同样的名称、余位、时段和下一步。若某项只换了颜色或圆角，就不算有用的方向差异。

## 比较两个真的不同的排法

下面两种都能选，适用场景不同。看哪种更贴近你预计的访客；你也可以直接说沿用其中一版、混合一处，或提出第三种做法，不需要先批准两版才能继续练习。

**方向 A：先按时间找。**适合学生通常先确定自己几点有空，再挑地点。

```text
14:00–16:00
明德楼    余 2 位   [看时段]
知行楼    余 7 位   [看时段]

16:00–18:00
明德楼    已满      [看时段]
知行楼    余 3 位   [看时段]
```

同一时段的地点挨在一起，学生不必记住第一间的余位再去找第二间；代价是想看某栋楼一整天，要跨组查找。

**方向 B：先按楼栋找。**适合学生下课后想留在某栋楼附近，先看那里何时有空。

```text
明德楼
14:00–16:00    余 2 位   [看时段]
16:00–18:00    已满      [看时段]

知行楼
14:00–16:00    余 7 位   [看时段]
16:00–18:00    余 3 位   [看时段]
```

一栋楼的时段连在一起，方便就近安排；代价是比较同一时段不同楼栋时，视线要上下移动。余位不能只靠颜色表示，写出“余 2 位”或“已满”，读屏和灰阶下也看得懂。

**你来试：**先假设自己“14:00 有空”，在两版中各找一处还能坐的地点；再假设“我必须留在明德楼”，各找可约时段。哪版少记一次信息、少来回找一次？若你自己的访客常按另一种条件决定，告诉 AI 用那个条件重排。

**AI 的建议：**如果学生的空闲时间通常先定，我会选 A；如果地点受课程或楼栋限制，我会选 B。当前没有真实使用数据，不能把这个推测说成用户研究结论。选定依据是你刚才实际执行的找法和主要使用场景。

## 做成样张，再改一轮

**AI 来做：**把选定线框做成能打开的单页样张，先用纯文字和基础按钮即可。让两行都能点到清楚的下一步，补一个“没有空位”的状态；不要添加虚构评价、登录要求或收集个人信息的表单。若两个方向都有吸引力，可以先留两张样张供比较；也可以直接按明确的主要场景做一张。方向选择是设计工具，不是审批门槛。

**你来试：**用手机宽度打开样张，不滚动先回答「今天 14:00 哪里还有位？」点一次“看时段”，确认页面给出下一步或明确说明尚未接通预约；窄屏下也能读完地点、时段和余位。再把浏览器拉宽到桌面，检查内容是否仍有合适宽度、是否居中或自然铺开；不能让文字横跨整块大屏，也不能把手机顺序硬拉成拥挤的多栏。真实预约尚未连接时，不要把按钮写成“预约成功”。

**反馈只改一件可观察的事：**别只说“再高级一点”。可以说：「在 390px 宽度，第一眼看见的是页名；我想先比较 14:00 两栋楼的余位。把日期标题移到页名下面，并让两条时段紧挨着。其他颜色和文字先保持。」AI 每轮只改这个层级，再用同一宽度、同一数据重看：第一眼能否读到日期和余位？结果若更清楚，就保留；若变差，撤回这项再试另一处。这样知道变化来自哪里。

**本课结束时**，保留首屏样张、手机和宽屏各一条观察记录，以及一项前后可比较的修改。投入真实预约时，余位由服务端读取，提交后根据实际占位结果显示“预约成功”或“已满”，并测试两人同时预约最后一位。实际功能按[交付验收](delivery.md)验证。选组件见[页面与控件](page-components.md)，参考其他网站时看[提取 UI 规则](ui-reference.md)。
