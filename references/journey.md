# 从正常入口走完一件事

接手已有网站做建议、修复或重构时，先打开当前页面。选一个有具体结果的任务，例如“我在手机上看到剪辑课程，想问能否带自己的素材练习”。从首页按可见文字找过去。直开表单 URL 可以单测表单，却会跳过课程难找、方向丢失等跨页问题。用户点名的其他入口若传入不同内容，也分别走通。

给建议时把能观察到的这一步写清楚，说明影响、首选改法和改后怎样验证。用户已委托修改时，在当前工程做完再走一遍。只收到图片时用位置说明看到了什么，可操作版本再验证点击和返回。

## 找出值得先改的一步

记下入口、当时能看见的选项、实际动作和结果。优先处理办不成、误以为办完、丢失输入，以及每次操作都要重找的地方。观察到一次重复填写，可以说明复现条件；其发生频率和造成的流失需要访问数据或用户观察来判断。

把“返回”还原成实际手势或控件。关弹窗、关抽屉、浏览器后退、审批成功后退出、切换校区可能走五条不同的路径。也要用页面标题和业务对象核对入口，例如店铺列表和商家认证申请可能属于不同页面。先在用户所说的入口核对哪一次操作确实丢了条件。只能读源码时，写清哪种解释有代码依据、哪个动作仍需复现，避免为相邻流程直接加缓存。

| 卡在哪里 | 怎样对照才看得出变化 |
| --- | --- |
| 手机看不出从哪里开始 | 记录视口和滚动起点，拍下首屏，再实际点到目标。记录打开菜单、翻页或滚动查找的次数。元素顶端坐标帮助解释变化，还要看按钮是否完整可见、会不会被固定底栏挡住。 |
| 跨页后重复说明来意 | 从两个不同来源进入同一表单，再从无参数的普通入口进入。检查能否带对、改掉、清掉默认值。换方向时只清掉失效的自动预填，保留访客手改的内容。 |
| 简单咨询要求填一堆信息 | 找出工作人员开始沟通真正需要的字段，用一句有意义的短需求和一段纯空白分别试填。阶段、预算等未知项允许留空。生成摘要后改原文，再复制一次核对内容。涉及正式审批时保留业务要求的材料。 |
| 一个手机既要看码又要扫码 | 实点同页二维码和可保存的原图，关闭后检查原文和焦点。剪贴板被拒时，确保文本可手动选取。分别记录“摘要已生成”“已复制”和真正的外部送达；微信相册识别用真机验证。 |
| 后台处理一条后又从头找 | 带测试角色、作用范围、筛选和排序进详情，再返回。若该条仍符合条件，恢复到原行；若处理后已离开队列，显示结果并落在相邻待办或明确的空队列。用当前权限重新取数，保留的筛选条件不能恢复过期记录。 |

只改与这个任务有关的模板、组件和入口。长时间编辑或多人交接时，再按[草稿与恢复](convenience.md)决定保存位置和冲突处理。访客只需辨认两个产品时，也可以用更清楚的排版省下一次选择。

桂小递的手机对照中，390 × 844 首屏原先只能看到第一款产品。第二款产品标题距页顶从 1003 px 移到 527 px。更重要的验证是从首页实际点进第二款产品，进入咨询后还能读到已选产品名。前一个证据解释可见性，后一个证据解释业务路径。[官网设计案例](ui-design-practice.md#桂校园团队的桂小递科技官网)

## 让交付的人能看到效果

用相同视口、同一份示例内容和相同起点再走一次。只改排版时，给同尺寸的前后截图。涉及跨页、手势或外部交接时，给可点击预览或一段正常阅读速度的短实录，让人看见输入、响应和最后状态。交付前实际打开链接并播放抽查。外发演示用测试内容。

可直接留下这一行记录：**入口和意图｜改前在哪一步卡住｜改后做了哪些动作｜实际得到什么｜在哪种环境验证｜还需验证什么**。后台额外记角色与测试对象；速度争议另用[同条件测量](delivery.md)。自动走通能证明该版本的路径可操作，转化率和真实用户是否容易理解仍需分别观察。
