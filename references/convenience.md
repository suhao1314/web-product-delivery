# 便利性设计：先找用户最怕重做的那一步

新增或改变草稿、筛选、状态恢复等行为时，按[网站开发四步](project-workflow.md#网站开发四步)先询问并确认需求。用户确认电脑端、手机端 PNG/JPG 图，再确认开发方案，才修改。

把代表任务实际走一遍，记下重复输入、来回找入口、等待无反馈、误操作和中断后重做的位置。每个候选功能回答四个问题：谁遇到、多久遇到一次、一次会丢多少工作、最省事的补救是什么。记录“采用 / 暂缓 / 已有机制足够”和证据。优先解决出现频繁或损失较大的一个断点；加入复杂功能前算上维护、权限、存储与隐私成本。

## 草稿如何选

| 真实情境 | 建议 | 验收目标 |
| --- | --- | --- |
| 公开官网选择服务、留一句需求或复制摘要 | 先在本次操作中保留返回修改和提交失败的输入。需求很长且常中断时，考虑由访客选择“暂存在本机”。联系方式与自由文本可能包含个人或商业资料，决定保存范围和期限前沿用原约定。 | 方向能预填；退一步无需重输；复制摘要后仍可编辑。静态站复制成功只表示访客拿到了文本。 |
| 个人用同一台设备编写长文、课程或多步申请 | 提供本机草稿并说明保存位置；再次进入显示标题和时间，可恢复、丢弃或继续当前输入。 | 关闭再打开可续写；删除草稿后不再提示；存储不可用仍可编辑和复制。 |
| 登录后跨设备续填、多人交接或有正式审核 | 当业务确有此需时，设计服务端草稿记录与权限。将草稿、待审核、已发布分开；定时保存可以接受不完整数据，提交时再校验所有必填项。 | 另一设备取到最近确认版本；同一条记录并发写入有冲突提示；审批和通知只在正式提交成功时触发。 |
| 共用电脑、敏感资料、退款或打款 | 选经授权的安全暂存范围；高风险动作只保留允许的工作上下文。资金凭证、验证码、令牌等排除出普通浏览器持久化。 | 换账号、换校区或登出后看不到他人的输入；恢复后仍需重新核对对象、金额和权限，禁止重复执行。 |

**有草稿时，把恢复也做完。**

- 只在有改动时合并写入；有进行中请求时排队或标识修订号。让旧回执只能确认它保存的那一版。显示“编辑中 / 保存中 / 本机已暂存 / 已同步 / 保存失败，可重试”中的真实状态；保存中继续输入仍保持未保存标记。
- 本机键至少区分项目、账号或匿名会话、组织和记录。记录格式版本、基础版本、更新时间与允许字段；定义过期、清除及账号切换策略。捕获配额不足、禁用存储和旧格式异常。附件未持久化时提示重新选择；不要显示虚假的上传成功。
- 恢复时对比当前表单、远端版本和草稿时间；已有输入或远端变化时展示差异或保留副本，避免静默覆盖。显式丢弃或正式提交已确认后才清理对应修订；请求超时先回查结果。共享设备只留项目允许的数据。
- 试一次：输入 A → 触发保存 → 再输入 B → 模拟 A 的回执迟到 → 断网退出再进入 → 恢复后提交 → 刷新查记录。再换一个账号核对隔离。验收记录明确哪些情况只能恢复 A、哪些能恢复 B。

## 除了草稿，还要检查哪些摩擦

需要重新安排按钮、表单、筛选区或手机布局时，用[按任务排版和补齐状态](ui-design-practice.md#按任务排版和补齐状态)把恢复机制画进真实使用路径。

| 观察到的问题 | 优先尝试 | 有效性的可见证据 |
| --- | --- | --- |
| 从产品详情去咨询还要重新说明来源 | 预填产品或课程方向，始终允许修改 | 从不同详情进入，各自带对业务；回退保留手改值 |
| 每天查同样的几组待办 | 先在列表→详情→返回之间保留条件、排序、页码与行位置；反复跨日复用时再加可命名的个人筛选视图 | 刷新/返回后继续处理原队列；入口清晰显示生效条件并能一键清空。公开的无敏感筛选可用 URL。内部账号、受限范围和敏感条件放在页面或受控会话里，换身份或范围就清相关状态，再按当前权限取队列 |
| 频繁给相似问题写同样的话 | 提供可编辑的常用回复，插入到输入框，预览后由操作者发送 | 替换商户名和缺失信息后再发送；模板过期可管理；插入本身不通知客户 |
| 经常误归档、加错标签 | 可逆操作保留短时撤销和操作结果；同步检查撤销权限与对象当前版本 | 撤销后刷新状态一致，并发变化有解释；外部付款、通知等按实际回执与补偿流程处理 |
| 列表太长、手机难找 | 默认聚焦高频字段，提供搜索、清空条件、无结果指引；确有批量需求时明确本页与跨页范围 | 操作者能定位一条测试记录，处理后回到原位置，失败项可单独重试 |
| 同一个动作要等很久 | 立即反馈正在处理，保留输入；长任务显示可返回的进度或结果入口 | 重复点不会多建记录；离开再回来能判断成功、失败或仍在处理 |

**衡量方式**：同一用户角色、同一笔测试任务，记录前后需要输入几次、返回几次、打断后需重做哪些字段、能否正确说出操作结果。若功能只增加了一个“管理设置”的入口，却没减少任何重做或错误，就先采用更简单的做法。

## GitHub 实例与取舍

- draw.io 的集成示例会显示草稿时间并让用户选择是否恢复。借恢复决策，生产项目另外设计账号隔离、数据范围和写入失败处理。[实现示例](https://github.com/jgraph/drawio-integration/blob/main/examples/localstorage/localstorage-svg.html)
- WordPress Gutenberg 的编辑器区分本地自动保存、恢复提示和离开时未保存提醒。适合长内容编辑中分开标识“暂存”和“发布”。[编辑器说明](https://github.com/WordPress/gutenberg/blob/trunk/packages/editor/README.md)
- React-admin 把用户保存的查询单列为可复用的过滤入口。可以先用原技术栈保存过滤配置，结果每次按当前权限重新取数。[SavedQueriesList](https://github.com/marmelab/react-admin/blob/master/docs/SavedQueriesList.md)
- GitHub 自身支持插入后再编辑个人常用回复，标记重复也有撤销路径。两者分别适合高频沟通和可逆整理。[常用回复](https://docs.github.com/en/get-started/writing-on-github/working-with-saved-replies/using-saved-replies) · [重复标记](https://docs.github.com/en/issues/tracking-your-work-with-issues/administering-issues/marking-issues-or-pull-requests-as-a-duplicate)
