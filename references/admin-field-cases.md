# 管理后台实操案例

以下案例是可独立复用的验收练习。所有对象均为虚构示例，不引用特定公司的历史记录、域名或内部测试数据。每次移植时按目标产品的角色、字段和状态重新设计。

### 1. 跨组织关联人员与草稿恢复

一个用户在组织甲登记，却负责组织乙的运营。创建管理员时，查找范围应按当前操作者获准查看的范围决定；新管理员的角色和组织决定其后续权限，不能把“被找到”误当作“获准管理”。候选列表只展示经授权用于辨认的字段。选中收件人后，通知偏好单独处理。

新建表单可恢复同一操作者未提交的非敏感字段；密码和验证凭据必须重填。编辑其他账号与新建草稿分开，创建失败保留输入，成功清除。复测时用虚构用户填到一半关闭、刷新、编辑别的账号再回来，再换操作者检查隔离。权限不足的操作者不能建立关联。

### 2. 待办角标与列表口径

准备待审核、异常处理和已办记录，逐项核对菜单角标与可处理队列。角标应只统计当前角色和范围可处理的事项；同一来源不重复计数。部分取数失败时保留已知信息并标明失败。让旧范围的慢请求晚于新范围返回，确认旧结果不会覆盖当前数字。

### 3. 售后阶段与资金事实

准备三笔样例：等待对方回应、支付渠道已受理但待确认、已确认完成但留有旧失败记录。逐笔核实当前责任方、期限、申请人、付款人和履约方。历史异常不能覆盖已证实的成功；同一对象的重复异常可合并，不同业务里的相同单号必须区分。只登记备注不能显示为退款已完成。

### 4. 临时查阅人员详情

在业务详情中打开关联人员资料，快速切换到另一位同名测试对象，再让前一次查询延迟返回。核对最终展示身份、关闭后原列表位置，以及无权限时敏感字段不可见。临时查阅适合侧边详情；以查找和管理人员为主的任务仍应进入专用页面。

### 5. 多范围内容编辑

在组织甲修改两段说明，取消切换并检查原文；再切到组织乙，模拟读取失败，确认不会把甲的文字发布到乙。预览应支持长文本换行，切换前提醒未保存修改，失败后清空旧范围内容并阻止误保存。

### 6. 线下奖品凭证与核销

为虚构批次配置每份数量、单位、可发份数、领取说明和期限。领取人先预览，确认后取得凭证；工作人员凭证查询对应奖品，实际交付后核销。复测时先预览后退出，再领取一份、查询凭证、尝试修改已领取奖品，并打开旧格式批次。只有涉及线下交付才需要核销；真实发放和现场扫描须另行验证。

**证据怎么用。** 自动化断言可证明特定版本的逻辑或页面契约；浏览器实录可证明操作者看到了什么、回到了哪里。两者都不能单独证明当前生产行为。复盘时只记录可复现且能改变设计决定的经验。
