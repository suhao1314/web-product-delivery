# 按页面任务找组件、定布局和选动效

动手前用真实内容画出阅读顺序。以示例服务官网为例，访客先看懂“能帮我开发什么”，再看产品实物，最后带着产品名称去咨询。示例产品值班员一打开审核页，就要认得当前校区、哪条在等他处理、点哪里看材料。两条路径各选一个最能说明业务的画面。品牌字体用真实中文名称试换行、缺字和加载前后的高度。在审核页把长名称、金额和状态对齐，让人能迅速对照。

## 去哪里找

1. 查当前页面的依赖清单、现有共用组件、相邻页面的导入和样式变量。优先复用带有本项目校区范围、焦点恢复或表单错误处理的组件。项目只有静态 HTML 时，链接、表单、分组、展开说明先用原生元素。
2. 找到同栈的控件后，先看相邻页面怎样用它。主操作、次操作、禁用、错误与焦点沿用已有变体和颜色变量。例如 Vue 后台可组合已有表格和详情抽屉，已有 shadcn/ui 的 React 工程可复用本地按钮和表单组件，静态官网可以直接用原生表单。现有控件缺能力或版本用法不明时，再查具体组件文档。[Element Plus 表格](https://element-plus.org/en-US/component/table.html) · [Reka UI 可搜索选择器](https://reka-ui.com/docs/components/combobox) · [shadcn/ui 组件目录](https://ui.shadcn.com/docs/components)
3. 需要引入依赖时，用一个实际任务试候选。给出首选、它补上的能力、手机键盘或触控的实测表现，以及新增资源与维护成本。复制代码或素材前核许可，浏览灵感站截取视觉规律时回到作者的源码或正式文档。用上游的思路改好本项目就够了。[Emil Kowalski 的组件选型方法](https://github.com/emilkowalski/skills/blob/main/skills/pick-ui-library/SKILL.md)

## 选一个和当前任务最接近的页面

| 页面与来访目的 | 阅读顺序、布局与组件入口 | 用什么动作检验 |
| --- | --- | --- |
| 品牌首页与服务页，判断是否值得谈 | 首屏一句主营、一处产品实物或品牌主视觉、一个明确主行动。次入口带到案例。复用现有导航、原生锚点和响应式图片。视觉构图与中文断行可参考[设计案例取舍](ui-reference.md)。 | 手机冷开先能读标题和点咨询。星河近尘与远云各自移动，手指局部拨开时仍能纵向滑页。[动效实录方法](motion.md) |
| 产品目录与案例详情，选择适合的产品 | 列表露出产品名、适用场景、实际画面。详情依次给用户问题、使用过程、能验证的结果和体验入口。示例产品、AI 共创界小程序等各自承接入口。先用普通链接与内容卡，产品多到难找时再加分类。 | 由卡片进到具体产品，手机返回时还能找到刚读的卡，再带着产品名称去咨询。 |
| 教学目录与课程方向，判断能学到什么 | 按学习目标分组。目录卡写预期产出，详情展示适合谁、要准备什么、作品示例和咨询。课程章节可用页内锚点或原生详情展开。 | 手机从目录选“AI 剪辑”，读到能做什么作品，再打开已带课程方向的咨询入口。 |
| 需求咨询或分步表单，说清需求 | 第一屏收最能决定下一步的字段，持续可见标签。出现多处错误时给可跳转摘要，长输入按丢失代价决定是否保留草稿。采用即时联系渠道承接时，结果页给可编辑摘要、复制反馈和真实联系入口。[GOV.UK 错误摘要](https://design-system.service.gov.uk/components/error-summary/) | 有草稿时输入一半离开再回来，能恢复原文。再试一次字段错误和复制失败，能定位字段、手动复制；“已复制”和“已送达”分别按实际结果显示。 |
| 运营看板，判断先处理什么 | 顶部标范围与统计时段。最急的待办数能进入同口径队列，趋势旁给单位和明细。两三个数字先用文字与表格；需要读走势才接已有图表。 | 点“待审核”能找到对应记录。加载失败显示重试，真实零条才显示 0。 |
| 审核队列与详情，连续处理 | 桌面用可筛选表格加详情抽屉，手机用记录卡和全高详情。头部保留校区、状态与申请人，底部放决定与下一条。Vue 看 [Element Plus 抽屉](https://element-plus.org/en-US/component/drawer.html)，已有 shadcn 的 React 项目看 [Data Table](https://ui.shadcn.com/docs/components/data-table)。 | 隔离数据中看完一页末条再看下一条，关闭详情后当前记录及其查看按钮可见，键盘焦点回到对应控件。 |
| 管理设置与异常工单，决定并知道后果 | 普通字段就地编辑，保存后读回。权限交接或异常处理用前后差异、受影响对象和一个写明结果的动作。可选缺件用行内提示，把需要人工决定的证据与动作放在一起。[首管与人工处理](admin-ownership.md) | 唯一超管用手机找到异常、看见原因、作决定并回读。取消退出保留原始记录。 |

## 动效落在哪个瞬间

给每种动效写下“触发动作、动的元素、应保持稳定的元素、打断后落在哪”。官网可用一处持续的品牌场景形成辨识度，首屏文字和按钮先就绪。抽屉进出可用短位移交代从哪里打开；连续审下一条时保持标题栏和按钮位置，直接更新内容和焦点。输入时光效停稳；告警用文字与图标表达。一秒内连点两次、切换减少动态效果、用触屏滚动，再看入口能否立即操作。按同设备同入口比较首个可操作时刻与连续操作耗时。沿用 CSS 或现有动效系统即可表达时，节省新依赖。[Emil 的动效筛选方法](https://github.com/emilkowalski/skills/blob/main/skills/find-animation-opportunities/SKILL.md) · [Motion 的减少动效适配](https://motion.dev/docs/vue-use-reduced-motion)
