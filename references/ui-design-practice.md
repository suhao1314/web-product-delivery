# 怎样判断一个网页好不好看、好不好用

设计一页之前，先写出访客此刻要作的决定。例如，初访者想知道团队能做什么，已经看过产品的人想谈合作。同一套品牌可以同时服务两个人，给他们的页面重点应当不同。

## 拿真实内容排一屏

| 要判断的事 | 试一个具体改法 | 怎样比较 |
| --- | --- | --- |
| 第一眼落在哪里 | 把一句业务主张、一行解释和一个主操作排在同一条对齐线上。让图像的亮部靠近想展示的主体，文字落在相对安静的区域。 | 固定文案和视口，缩小首屏查看明暗分布，再回原尺寸读。请第一次看到页面的人指出团队做什么、下一步可以点哪里。 |
| 中文是否有节奏 | 短标题可试有笔画对比的展示字，正文和控件选小字号下清楚的字体。按语意换行，标题与解释靠近，两组内容之间留出更宽的间距。 | 换成长产品名，分别看桌面、窄屏、字体未下载和文字放大的状态。发生孤字、截断或按钮被挤出时，调整字号、行宽与排列。 |
| 控件能否一眼分清 | 一组操作里，给此刻最重要的动作用实心按钮，探索入口用文字链接。用位置、边界和文字区分选中、焦点与错误。 | 关掉动效，用键盘走一遍，再用手指点一遍。观察当前焦点、点下后出现的反馈、失败后从哪儿继续。 |
| 不同页面是否像同一家 | 保留字体分工、强调色和按钮含义。让首页靠构图带出品牌，让课程列表用对齐的标题与学习成果帮助比较，让表单把标签、字段和提示排成一组。 | 用同一产品名从首页走到详情和咨询。每一页都应能认出正在看的对象，以及此时的主要动作。 |

## 让设计稿经得起评审

- **拿真实内容试一次选择。** 例如摄影站让访客比较两组作品，课程站让访客比较两门课。两组资料用同一组真正影响决定的字段，检查谁能回答“适不适合我、下一步点哪里”。首页负责说明价值和入口。对候选记录的比较需求，优先用对齐的列表或表格。
- **每张稿检查主体、字和秩序。** 用一个放大的产品实拍、代表作品或主张做主角。缩小看明暗、留白和主操作的位置，再还原到实际字号读最长中文、小字说明和按钮。统一重复元件的字级、间距、边界及选中反馈。把容易误认成可点的装饰收掉，也用键盘和手机设计状态检查当前焦点会落到哪。
- **画到能判断行为为止。** 用同一组例子画首页与内页、宽屏与窄屏、正常与最会发生的异常。读一遍导航、表单、返回和反馈。批量操作或搜索用真实行数，有图片就验真实比例。动效表现写触发、范围、恢复和触屏取舍。
- **交实物与可复验的判断。** 输出实际可打开的稿，指出哪处值得保留、最妨碍用户的一项、推荐改法和验收动作。参考站提供构图、控件或页面顺序的证据，成品使用项目的内容与风格。方向确实未定时，用相同数据比较明显不同的排法。操作能少走一步、可辨认重点且稳定的方案优先。

## 按任务排版和补齐状态

画稿前写一条真实路径，例如“从产品页进咨询，写出需求，拿到可发送的摘要”。标明用户此时要判断什么、点哪里、看到什么算办成。用同一条路径决定留白、主色、内容顺序和状态稿。遇到已有页面，先走一遍这条路再选优先改的位置。

| 用户想做什么 | 界面怎么排 | 怎样在浏览器验 |
| --- | --- | --- |
| 进来就知道点哪个 | 首屏让产品、短说明和一个主动作形成清楚的阅读顺序。用实心按钮突出当前目标，探索链接保持易找。按钮写清实际后果，例如“查看微信打开方式”“生成项目摘要”。 | 在手机首屏读到用途，再点主按钮。核对弹层、跳转或摘要是否与按钮说的一致。 |
| 快速扫读并找到一条 | 用组标题、留白和细分隔线组织相关内容。桌面要横向比较的字段用对齐的表格。手机需要挑一件再处理时，让名字、状态和常用操作先出现，展开可看其余字段。筛选摘要留在结果旁。 | 用长名称和真实行数找一条，再从详情回到原结果。手机点行操作时检查误触，桌面批量操作有需要时再核对选中数量和作用范围。[Carbon 表格指南](https://www.carbondesignsystem.com/building-blocks/core/components/data-table/guidelines) |
| 快点填完，有问题能改 | 从当前结果反推需要的字段。相关标签、输入和提示放在一组，低频选项用有名称的折叠区。确实需要复核的提交可显示简洁摘要，每组有对应的“修改”入口。 | 从来源页进入时已有选择能预填。故意漏填后，在短表单就近指出怎么改。长表单出现多处错误时可从错误摘要跳到字段。返回修改保留原输入。[GOV.UK 展开细节](https://design-system.service.gov.uk/components/details/) · [核对答案](https://design-system.service.gov.uk/patterns/check-answers/) · [错误摘要](https://design-system.service.gov.uk/components/error-summary/) |
| 单手点到常用操作 | 让高频控件有充足的点击面积和字距。长页里主操作确实常丢时，才试固定在底部，并留出内容与键盘空间。危险操作独立呈现，给它说明对象与影响。 | 用窄屏、软键盘和 Tab 走一遍。检查末项能滚出，焦点可见，手指点相邻操作时目标清楚。[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) · [避免焦点被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html) |
| 看懂空白、失败或已办成 | 为实际可能发生的首次无内容、筛选无结果、加载失败和成功回执画状态。短标题说现状，一句说处理办法，就近放对应操作。例如“当前条件无结果”旁放“清除筛选”。对齐、字级和留白沿用同一套，状态靠文字加边界或颜色辨认。 | 用空列表、找不到的关键词和断网分别触发。检查能清条件、重试或继续编辑。状态文字与真实结果一致。[Carbon 空状态](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states) |
| 回来接着做 | 详情保留可辨认的对象标题。列表返回后，已选条件、上一行和下一步操作都处在预期位置。长任务是否要加草稿，再按中断次数、隐私和重做成本决定。 | 按“筛选 → 打开一条 → 返回 → 处理下一条”走。用键盘核对返回焦点，再用触屏核对滚动位置。[恢复与便利性](convenience.md) |

审图给出一条主路径和该任务会遇到的典型异常。能操作后，用相同角色、数据和手机宽度重走。记录额外寻找入口、重复填写和被迫返回的次数，同时检查版式层级与焦点。走通正常状态与恢复路径后，页面才算好用到位。

**小程序配套网页。** 如果主要目标是让访客体验产品，把“查看微信打开方式”放到首屏主位，“看共创案例”放在次位。弹窗交代搜索名称，能复制时给实际反馈，浏览器拒绝复制时让访客选取原文。调整前后用同一手机宽度从页头和正文分别走一遍，确认访客知道接下来去微信做什么。

**可以直接试的练习。** 在离线样站的山野咖啡案例点“带着这个方向去咨询”，看所选方向有没有跟过去。填写需求并生成摘要，核对页面的按钮和反馈有没有说明实际结果。再用自己的业务内容替换文案试排。[离线样站](../assets/site-starter/index.html) · [咨询表单](../assets/site-starter/inquiry.html)

## 高保真审图

### 取用真实产品画面

网站展示已有产品时，从正常入口进入用户要看的页。小程序展示首页时，从首页标签或已知启动路径进入，核对标题、选中的导航和首屏内容。保存一张完整原图，旁边标明页面、版本或环境、录制设备、视口和数据状态；摆入设计稿的裁切图可以回到这张原图。预览版、正式版和真机实拍按实际来源标注。获取不到目标页面时，在示意图中标出待补素材的位置。

### 选一个首屏主体

写清这页服务谁、对方最该看见什么、下一步最常做什么。官网可以用实拍界面、代表作品或真实使用场景作为主体。列表与后台把用户接下来要处理的对象和当前条件放在明显位置。把图缩小或转成灰度看一遍。第一眼落到装饰或同等醒目的次要内容时，调整主体的面积、明暗和四周留白。

用一条对齐线串起标题、解释和主要按钮。辅助入口通过字重、描边或文字链接降低权重。手机按任务顺序重排为单列，先保留主体与主操作。需要移走的案例、拓展内容和气氛图放到下方。

### 用真实中文定排版

先换入真实产品名、最长的按钮文案和两到三句中文解释，再决定字形、字重、换行与间距。画出页面基础版式后，记录可复用的标题与正文字体、颜色用法、内容宽度、行距和内外边距。按钮、输入框等同类控件沿用这些决定。

| 检查项 | 如何设计 | 如何复查 |
| --- | --- | --- |
| 字体职责 | 展示字体给短标题表达气质。正文、表单和按钮选小字号下轮廓清楚的字体。把品牌名里的中文与拉丁字母一起试排。 | 检查系统回退字体、文字放大和最长文案。标题仍能按语意换行，控件不被挤出。 |
| 层级与留白 | 先排标题、正文、说明的字级。相关文案和控件靠近，组与组之间留出更宽的距离。 | 缩小图看主次，再回原尺寸读每一行。窄屏给长说明增加行数，保留按钮可触面积。 |
| 色彩与背景 | 给正文、次要文字、主要操作和错误状态分别定颜色。大图或明暗变化明显的区块给文字留稳定底色。 | 在最亮与最暗的背景各看一遍。状态结合文字、边缘或符号表达，颜色有变化时仍能读。 |
| 阅读和操作 | 按访客的任务次序安排内容、可点击元素和焦点。用相邻页面检查哪些规则需要统一。 | 从上到下读一遍。上线前用键盘和触屏走主操作，并核对页面的阅读顺序。 |

### 把立体材质画出来

将主体的正面、倒角、侧壁与投影画成不同层。选一个光源和视角，让亮面、暗面和阴影方向一致。放大一角核对透视、转角和遮挡，回到实际尺寸检查框体占了多少面积。展示真实界面时，核对合成图是否压住导航、扭曲文字或留下接缝。

把有厚度的框体优先用在产品主视觉或重点预览卡。普通卡片、表格和输入框用更轻的边界。表单聚焦与输入时保持位置稳定，错误、必填、聚焦等状态留清晰的边线和说明。

### 画出边缘流光与操作状态

为局部特效画默认、触发和恢复三种状态，并标出触发方式、作用范围和持续时间。例如指针靠近产品主视觉时，让亮边沿右上倒角短暂掠过，完成一次后恢复。主体截图、标题和按钮保持稳定。有点击行为的控件保留独立、清楚的键盘焦点。产品主视觉纯展示时保持正常的阅读顺序。

把触屏版和跟随系统减少动态效果的静态状态也画出来，保留倒角和厚度。用状态图说明选中、展开、复制、保存等反馈怎样发生。涉及失败或重试时，标出下一步操作的位置。[动效验收方法](motion.md)

### 用同条件比较并交审

候选方案保持同一视口、中文文案、截图入口与数据状态。交桌面、手机和对应状态的设计图，必要时附局部放大。图稿回答主体是否清楚、中文是否好读、主操作是否容易找到、动画怎样提示状态。点击、性能和实际动效等结果留到可操作版本验证。

选一个首选方案，说明哪里更适合真实用户。按[页面审图流程](visual-direction-and-change-control.md#先审图再开发)等待用户确认，随后补缺失素材并定建法。

### 小程序配套网页的首屏

第一稿把工具箱页面和学习计划并排放进首屏，访客很难把其中一项认作整个小程序。审图时从微信开发者工具打开小程序首页，核对了顶部标题、快捷入口和选中的首页标签。新稿把首页实拍居中置入主视觉，学习计划下移到案例区。中文标题用展示字，说明与按钮用无衬线字。桌面图能放大看到倒角与侧壁，移动图保留同一个首页画面。边缘流光随交互状态图评审。

## 桂校园团队的桂小递科技官网

**首屏的两处亮点各有用途。** 桌面首屏右侧的银河亮带给画面尺度，左侧暗部衬出“把 AI 想法，做成可用的产品。”。带衬线的两行大标题负责表达主张，下方小字补上“智能体、软件定制与流程自动化”。浅色实心按钮“定制我的项目”给有明确需求的人；“看产品”“学技术”放在旁边，想先了解的人也有入口。移植到摄影工作室时，把银河换成自己的代表作品，再找一块能放标题的留白。手机重新裁图，看清人物或产品主体，也给文字与手指留位置。

**把“浩瀚”说成可以看见的运动。** 这个项目曾收到“像一张图在转”的反馈。评审时固定镜头，先让指针静止，看近处星尘能否缓慢掠过远处银河；再横划一小段，看手势附近有没有被拨动、远处会不会跟着整片偏移；松手后试自然纵向滚动。标题与按钮应当稳定，跟随系统减少动效时也能从“看产品”进入产品页。桌面实拍可以判断构图，局部运动要用连续画面验证。按需参考[分层动效的对照方法](motion.md)。

**让选过的内容跟着访客走。** 在产品页点“AI 共创界”对应的“咨询合作”，咨询页带出“产品与其他合作”和“AI 共创界”。只有“你想做什么？”必填，时间和预算折叠在选填项里。访客生成摘要，发现写错可点“返回修改”，改原字段后再生成；复制之后由访客自行发给企业微信。走查时分别从产品入口和直接打开咨询页进入，比较两次初始状态。用真实控件的回执区分生成、复制和发送。案例采用团队本地浏览器中的维护版本。[桂小递科技官网](https://guixiaoyuan.site/)

## 把评图变成一次可交付的改动

保留相同内容和视口，先改影响判断最大的一个关系，例如把亮带从文字后面移开。交付时用两张同尺寸截图指出哪里更容易读，再给一段实际操作说明哪一步省了。若只能验到模拟手机，就写明设备和范围；只有做过用户观察才写观察结果。

可以直接这样交代 AI：“我希望初访者打开首页就知道我们做什么，想定制的人能马上联系，来学习的人也找得到入口。请保留品牌图，用同一段中文试两种排法，说明你选哪种、为什么，再在手机宽度从产品走到咨询。”
