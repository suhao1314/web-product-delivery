# 性能、验收与发布

## 先分清用户说的“卡”

| 用户能指出的现象 | 记录什么 | 优先验证的假设 |
| --- | --- | --- |
| 点开后很久才出字 | 首字节耗时、重定向、字体与阻塞样式、首屏绘制轨迹 | 同一版本在本机快、公网慢时，分开看连接、服务端响应和下载 |
| 字出来了，图一截一截显示 | 浏览器选中的实际图片 URL、体积、解码尺寸、预加载及主体元素 LCP | CSS、预加载和动效纹理是否重复下载；是否提早加载了二维码、次屏图或大字体 |
| 滚动或手势发涩 | 主线程长任务、帧间隔、重复布局、GPU 画布像素量、是否离屏仍绘制 | 暂停动画实测对照；缓存尺寸、预绘重复图形或降低慢设备分辨率后再试 |
| 点保存像没反应 | 输入到下一次绘制、请求发出与响应时间、界面状态、服务端是否已写入 | 将按钮反馈、网络等待与数据一致性拆开查；等待结果时保留输入，避免误重复提交 |

保留基线版本和入口。同一浏览器、视口、DPR、缓存、账号状态、网络条件和观察窗口内交替访问两版，留下每次样本、缺失项和中位数。FCP 看首次绘出内容的时刻，LCP 看视口内最大合格内容的绘制时刻。要判断标题何时可读、按钮何时能点，另看对应元素和真实操作。需要解释某个改动的贡献时再做单因素对照。线上数据可用时按设备分组看第 75 百分位，输入响应和布局稳定性分别检查。[FCP 定义](https://web.dev/articles/fcp) · [LCP 定义](https://web.dev/articles/lcp)

**测量记录模板。** 记录设备模拟条件、缓存状态、网络限制、运行次数和观察窗口；逐次报告成功、失败与缺失样本。只有条件一致的前后数据才能比较。字体、图片和加载策略同时改变时，结果只说明整版差异，不能归因于某一项。\n\n排查类似页面时先看实际请求，找手机是否下载了桌面首图、重复纹理或整套中文字体。按画面裁切选图，优先保留承担品牌识别的字形。试用系统正文字体后，再用窄屏检查中文回退、标题换行和按钮是否移位。后台的慢点若在筛选后才出现，应计时到正确结果可操作，并核对旧请求晚到时最终显示的条件。

## 浏览器验收样例

若请求时间线显示多个读取首尾相接，先确认数据依赖。例如课程介绍与同页公开案例可独立加载，先返回的区域可先显示；审核详情则要先确认当前账号和校区范围。只有相互独立的读取才并行。让较慢的一项延迟或失败，再看主操作能否使用、报错是否只影响对应区域。

已有浏览器时，从用户说的入口实际操作。未配置下方的可选测量脚本时，可用浏览器开发者工具的 Network 和 Performance 面板记录同条件冷开，再点一次主按钮。无法运行浏览器时只报告静态发现，并标明缺少哪段运行证据。

1. 按风险选择代表路线及状态。公开站从深链接进详情，再去表单；后台用测试夹具从排队列表到处理结果。用项目已有的自动化框架，按可见名称和角色定位；等待具体的可见结果或回读响应。长轮询应用等待网络完全空闲会误判。
2. 桌面和目标手机各从正常入口运行，带上用户反馈的截图尺寸。点主按钮、键盘走焦点、临时断网试重试、返回再刷新。检查页面错误、失败资源和横向溢出；长文本、零条结果、失效链接选与本次修改有关的情形。
3. 表单检查标签、必填说明、首个错误定位、错误后值保留、提交期间状态和重复点击。弹窗有可访问名称，焦点进入、循环并在关闭后回到合理触发点。小屏测试屏幕键盘遮挡和粘性底栏；色彩以外给状态加文字。自动无障碍扫描和实际键盘/读屏检查分别记录。
4. 视觉看浏览器实际渲染；交互断言操作后的可见状态或服务端结果；动效看连续帧。说明哪些是模拟手机、真机、示例数据、真实账号。截图和日志用脱敏测试数据。

## 获准上线时

定位真正托管入口、对外域名和目标目录，尤其注意同机官网与管理端。静态站按明确清单打包，排除密钥、配置备份和内部文档。记录版本、清单与摘要；先备份现网将变更的内容并留出可执行的回退路径。静态资源用可缓存的新名字，先传资源，然后切 HTML；支持版本目录的托管优先用整体切换。数据库变更独立评估新旧应用兼容、备份和恢复方式。

把待发布目录当作静态站启动，用浏览器从正常入口走到本次修改的页面。对登录后的懒加载页面，可以在本机模拟接口响应，让浏览器加载真实的打包资源。记录入口、资源清单和实际加载分包的摘要。只要分包发生变化，就用新包重跑，即使入口 HTML 完全相同。分包一旦变化，就用新包重跑对应检查；入口 HTML 未变也不能代替分包验收。

从公开 HTTPS 正常入口验证当前版本、深链接、字体/图片、帮助页、移动导航和咨询路径；有 CDN 或 Service Worker 时核实取到的新版本。静态交付可自动逐项比对清单摘要；动态 HTML 用版本标志和业务断言。若关键资源错版、入口不可用或关键流程失败，停止扩大发布，恢复上一版并复查。无法确认托管时照常交付本地成品，指出具体缺哪一种权限或配置。

**交接可直接这样写**：“我在［版本 / 环境 / 尺寸 / 角色］操作了［步骤］，看到［实际结果］，证据在［位置］。生产已核对［范围］，待验证［真机或外部能力］。若［明确异常］，可从［备份或版本入口］恢复。”

## 可复用的冷启动测量

在技能目录运行下列命令，把地址换成已授权测量的具体入口。使用已有的 Playwright 和 Chromium。需要时用 --playwright-core 与 --browser 指定路径。默认输出 JSON 到终端，--output 可指定新的临时报告路径。

```sh
node scripts/measure-page.cjs --url http://127.0.0.1:4173/ --width 390 --height 844 --runs 5 --observe-ms 3500
```

需要手机弱网对照时，可采用这组条件。带宽按十进制千比特/秒填写，1600 kbps 等于 200,000 B/s。

```sh
node scripts/measure-page.cjs --url http://127.0.0.1:4173/ --width 390 --height 844 --dpr 2 --mobile --touch --cold-cache --latency-ms 120 --download-kbps 1600 --upload-kbps 800 --runs 3 --observe-ms 3500
```

FCP、LCP 从导航开始计时。此工具在 DOMContentLoaded 后再收集指定时长，与基于 load 事件的测量采用不同截止点。前后比较用同一种方法。逐次样本、成功数和缺失数随报告输出，观察窗太短时延长后两版一起重测。资源统计限于观察到的子资源，排除导航 HTML，部分跨域资源的字节数可能不可见。

每次测量新建浏览器上下文，进程和系统 DNS 缓存仍可能复用。对照前实际打开目标，核对登录状态、标题和业务控件，尤其留意返回 HTTP 200 的登录页或空壳页面。设备参数用于浏览器模拟；手机芯片、微信内置浏览器、生产网络和真实交互分别验证。这个加载探针不产生 INP。[Playwright 设备模拟](https://playwright.dev/docs/emulation)
