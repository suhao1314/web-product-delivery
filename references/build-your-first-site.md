# 带第一次做网站的人走到上线

按[网站开发四步](project-workflow.md#网站开发四步)带用户做网站。每个新任务先问清并确认需求，随后交电脑端、手机端 PNG/JPG 图片，等用户审过两套再给开发方案。下面新建文件、启动项目和接通入口的操作从用户明确批准开发方案后开始。已提供的资料可以用来把问题问准。

## 第一轮怎么说

当用户同时想做搜索、草稿、问卷等功能，先问最常见的使用场景和本轮解决范围。需要复现时用获准的已有环境只读查看。[功能选择与轻量替代](feature-tools.md)

只有一句“我想做个网站”时，先读用户已经给的业务、工具和素材。可以这样开口：“这个站主要给谁看？他看完后，你最希望他做哪件事？”对方说想做报名、预约、咨询时，再问一句能改变成本的问题：“你要收到整理好的文字，还是要系统把每条都存起来，让团队登录处理？”给一个有理由的首选，沿用已经答过的信息。

例如，工作室想展示作品并用现有渠道了解拍摄需求。先问访客怎么选作品、咨询结果交给谁。用户确认后，交电脑端和手机端各一张带真实内容的 PNG/JPG UI 图，画清从作品到咨询的入口。图通过后出方案，等用户明确同意，再接出真实可操作的两页。

## 从第一张草图到第一条可用路径

| 做到哪儿 | AI 负责什么 | 用户亲手试什么 | 这步留下什么 |
| --- | --- | --- | --- |
| 定首版 | 先问来访者、首要动作和本轮范围，再复述。 | 明确确认本次需求。 | 用户认可的任务和范围。 |
| 设计 | 用真实或已标注的内容交电脑端、手机端 PNG/JPG 图片，画清入口、主要动作与状态。 | 查看并确认两套图片。 | 两端图片和用户审图确认。[第一屏设计练习](first-page-workshop.md) |
| 定开发方案 | 图片确认后说明页面怎么接、数据由谁接收、开发顺序与怎么验。 | 看过后，明确同意按本方案做。 | 获准的开发范围与验收方法。 |
| 跑起项目 | 开发方案批准后用现有工程，或从[教学样站](../assets/site-starter/index.html)改造。沿项目实际入口启动。 | 打开首页验证。 | 运行入口和实际开发版本。 |
| 做通业务 | 先接首页主按钮、第二页输入和真实交付动作。按开发方案每接好一段就从正常入口运行。做产品、教学等更多页面时，复用导航、字体和按钮，并把访问来源带到下一步。 | 从首页点到最后，用一条虚构需求试成功、空输入和返回。再直接打开第二页。 | 一条能办事的路径。若仅生成摘要，状态写“已生成”，接收方由谁联系写清楚。 |

### 想亲手从空文件开始

新建一个空的练习文件夹，先写下面的 `index.html`。让用户双击它、读出标题，改一个词再刷新。AI 让用户指出两处标题。`title` 写在浏览器标签上，`h1` 写在页面里。`p` 放正文，`a` 放访客能点的链接。

```html
<!doctype html>
<html lang="zh-CN">
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>我的摄影作品</title>
  <main>
    <h1>为社团记录活动现场</h1>
    <p>我拍舞台、幕后和散场前的最后一张合影。</p>
    <a href="inquiry.html">告诉我活动时间和拍摄需求</a>
  </main>
</html>
```

接着在**同一文件夹**新建 `inquiry.html`，从首页复制骨架，给第二页换标题、写上想了解的两项需求，把链接改成 `<a href="index.html">返回作品首页</a>`。验收时从首页进去，再从第二页返回。等两页通了才加样式：两个文件都在 `<title>` 后引入 `<link rel="stylesheet" href="site.css">`，创建同名文件，写一条 `main { max-width: 44rem; margin: auto; padding: 1.25rem; }`，刷新两页观察留白。学习表单时再对照下面完整样站的输入和生成逻辑。已有明确交付目标的用户可直接从样站或现有工程开始。

### 从可运行样站开始的三个动作

1. 从本技能目录或完整技能 ZIP 中找到[微光工作室样站](../assets/site-starter/index.html)，把整个 `assets/site-starter` 文件夹复制到练习目录。双击副本的 `index.html`。用文本编辑器打开同一文件，找到 `<h1` 开始的主标题，将标签里的文字改成自己的业务标题，保存，回浏览器刷新。HTML 决定有什么内容。只用聊天工具时，让 AI 每次给出一个完整文件的名字、内容和保存位置；有工作区工具时由 AI 复制并打开。
2. 打开 `site.css`。在顶部 `:root` 找到 `--accent`，把它的值改成 `#155b52`，保存并刷新，观察主按钮的底色，再缩窄窗口看中文换行。CSS 决定内容怎么排、怎么显示。
3. 从作品入口去咨询，填入“我想在下个月展示三件作品”，生成摘要，再手改一句并复制。对应的浏览器脚本负责把输入变成反馈。关闭网络再试一次。要真正收到咨询，项目主人需提供可公开使用的联系渠道；AI 接好并测试后再发布。分辨“在访客电脑上生成”和“工作室已收到”。[网页入门练习与术语](https://developer.mozilla.org/en-US/docs/Learn_web_development/Getting_started/Your_first_website)

**遇到打不开。** 先让 AI 使用用户实际点的入口复现。双击 HTML 出现源码时，检查扩展名是否成了 `.html.txt`，并用浏览器打开。样式缺失时，看 HTML 引用的相对路径、文件大小写、是否只复制了一个文件。已有框架项目由 AI 检查启动脚本并运行开发服务，给终端实际显示的地址。手机上的 `localhost` 指向手机自己；跨设备验收用获准分享的预览地址或同网络内的测试服务。

想练习“网址打开网页”且电脑已有 Python 时，在包含 `index.html` 的目录打开终端，执行 `python -m http.server 8000 --bind 127.0.0.1`。用这台电脑访问 `http://127.0.0.1:8000/`，结束时回到终端按 Ctrl+C。若提示端口被占用，可把命令和地址里的 8000 一起改为 8001。无 Python 的静态练习继续双击打开即可。

### 哪些站需要后台

- **展示、产品、教学或咨询。** 访客只需阅读、查作品、生成需求，现有联系渠道能承接，先用静态文件。需要员工经常改内容，再评估复用现有内容管理工具。
- **多人报名、预约或运营工作台。** 出现“第二台手机也得看到”“两个员工不能同时占到最后一个名额”时，要有共享服务。先讲一条最小实现：表单 → 服务端校验 → 保存一条虚构记录并返回编号 → 授权员工在列表中看到并处理 → 访客能查到正确状态。AI 据此定数据字段、状态转换与权限，接入已有服务优先。两台独立浏览器会话重测，同时抢最后一个名额只能成功一次；跨角色访问要验证权限。在用户接受数据责任与维护成本后选托管。需要登录的产品走[后台设计](admin.md)和[负责人交接](admin-ownership.md)。

## 下一次对话怎样接上

用[确认记录小样](project-workflow.md#跨对话怎么接着做)记住用户确认过的范围、两端 UI 和方案版本。开发获准后，可以把下面这段填入项目**已有**的 README 或进度记录。短练习记在对话里即可。续做先核对确认，再对照实际入口和已验结果。

```text
本次目标 / 已决定：访客看一个作品，编辑咨询摘要，自己联系工作室。
已走到：本地两页可点；窄屏检查通过。预览和正式地址尚未建立。
从哪里接：在项目目录打开 index.html，进入作品页并生成一条虚构需求。
仍缺什么 / 谁负责：工作室提供公开联系入口；AI 接入后验证能找到接收方。
下一步：用手机从作品一路走到联系人。发布授权及目标环境另记。
```

如果对方今天只能做一点，给他现在打开的文件、一个能试的动作和成功时会看到的结果。已上线的网站只改一个页面时，先询问并确认这一处的要求，再给两端图片，出方案并获准后修改。
