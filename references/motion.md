# 网页动效的选型、开发与验收

## 开发时默认走这几步

先向用户询问并确认需求。出图、确认开发方案和编码按[网站开发四步](project-workflow.md#网站开发四步)执行。

1. **找实际页面和参考。** 从访客的正常入口看首屏、滚动、切换和操作结果。遇到新的视觉方向或交互，自行找同类产品的网页和可操作样例。记下参考的页面、位置、动作和用户看到的变化。优先看项目已有组件、原作者的演示、开源源码及官网说明。用户只给几个效果时，自行补齐适合该任务的候选。[网站及组件参考](motion-patterns.md#找什么参考怎么借鉴)
2. **逐段选效果。** 检查入口、阅读、画面探索和业务反馈。用下面的场景表和[动效图谱](motion-patterns.md#十六种可操作动效)选出能突出主体、帮助理解步骤或报告状态的效果。适合的几项可以组合使用。试一遍哪一项会同时抢走注意力、移动点击目标或增加等待，再调作用范围和节奏。
3. **画进两端图片。** 在电脑端、手机端 PNG/JPG 图中标出作用对象、触发、可见变化、结束状态及触屏表现。让用户确认当前两套图，再把相应动效写进开发方案。
4. **方案获准后把效果接进交付页。** 先用项目已有组件和原生 CSS、浏览器能力。可从[离线样例](../assets/motion-lab/index.html)取对应结构、样式和监听代码，套本项目的素材和样式。只有现有做法承载不了同步动画、滚动时间轴等需求时，才评估现有框架适配的依赖。页面内容、链接、按钮和操作结果先正常工作，动效跟随真实事件。
5. **用浏览器收尾。** 在同一视口对比常态、触发时和恢复后。手机以触屏滚动和点按验，键盘走到有交互的元素并检查焦点。交付时写清用户可以在哪个区域看到效果，以及结论来自本地浏览器、模拟触屏还是真机。

## 按页面和动作选用

| 当前任务 | 可以优先搭配 | 看什么决定加上 |
| --- | --- | --- |
| 官网、产品首页、作品展示 | 真实主体进场，产品框局部流光、聚光或轻倾斜，次屏滚动显现或按阅读顺序错峰 | 鼠标和手机能先认出产品。菜单和主按钮稳定。实拍中的文字不因透视失去可读性。 |
| 体验流程、案例或教程 | 分步叙事、阅读进度、前后对比、同一物体的连续转场 | 每次动效能指明阶段、证据或操作差异。章节可直接到达，窄屏单列仍能看完。 |
| 功能页、表单和后台 | 页签选中、展开收起、提交中、成功或失败、安全撤销、回到列表的反馈 | 用户能继续看当前对象、焦点和真实处理结果。跳动、闪烁或长等待会降低处理速度时保留短反馈和清楚文字。 |
| 品牌展示、数据故事 | 材质微光、局部粒子、数字递增、互动文字或有限次走带 | 确认内容真实且完整可读，装饰动效给正文、数字和操作让出主要位置。 |

多处控件默认用同一套时长和缓动来表达相近的状态。可以从点击反馈约 120–200 毫秒、内容淡入约 180–320 毫秒、主视觉局部扫光约 600–900 毫秒开始试。时长以设备、位移和真实操作节奏为准。快速再次点击应先更新当前业务状态，并能中断或替换旧动画。

## 在成品中验收

- 先说清谁固定、谁自己动、输入影响哪里、移开后如何恢复。同一版本、路由、尺寸与状态录制或对比，必要时抽取触发前、半程和结束帧。截图能证明构图，连续帧或操作结果能证明运动。
- 对真实任务检查点击区域、可读文案、焦点和反馈。鼠标专属效果要有触屏可用的稳定页面。启用系统减少动态效果时，内容完整，交互依然可用。JS 禁用或特性不支持时保留可读的基础路径。
- 首屏的标题、按钮、静态画面可先读先用。持续绘制只在场景需要且可见时运行。优先检查 transform 和 opacity 是否够用。涉及画布、滤镜、大图层或持续跟随时，按实际帧间隔、长任务、加载和滚动表现查成本。[高性能动画指南](https://web.dev/articles/animations-guide) · [系统减少动效](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)
- 项目既定页面不提供暂停或音效开关，用短促、有限次的自动动画，跑马灯可改成静态或用户触发。无可控方式时保持装饰内容静态。WCAG 2.2.2 对自动运动和自动更新分别有适用条件，涉及持续动效或实时数据时按具体场景核对。[暂停、停止、隐藏](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)

**小程序配套网页实测。** 这个页面用真实小程序首页作为主体。首屏图短进场，产品框受鼠标触发只扫边一次，工具画面入视口淡入，功能切换和微信弹窗用短反馈。本地 Chromium 检查了扫光中两帧、手机框的位置、390 像素触屏、减少动效和弹窗关上后的焦点。制作新项目时，仍从它自己的内容和动作出发。

## 大画面和局部跟随排查

用原尺寸预览校对字体、画质及文字遮挡。先排除旧资源缓存、错误视口、截图裁切和系统的减少动效偏好，再核对图层。

| 用户的说法 | 先判别什么 | 怎样证明改对 |
| --- | --- | --- |
| “像一张图在转” | 摄影机、整幅纹理是否一起旋转；是否存在尺寸和速度不同的运动参照 | 固定镜头录两段，指针静止时近尘穿过远星，远处气体内部缓动 |
| “鼠标撩一下那一小片” | 输入位置是否来自可见画布；裁切、CSS 像素、DPR 和 Y 轴是否匹配 | 固定随机种子及动画时刻，有输入和无输入各绘一帧，命中区域变化，远处对照块一致 |
| “动效明显一点，手机也看得见” | 手机首屏裁切、近景初始分布和触控事件；手机没有 hover | 无触摸先录自主运动，再横扫局部、松手回落，最后纵向滑动页面。检查取消手势后能恢复 |
| “粗糙、全是白点在跳” | 先看原图、运行图与真实合成图，再定位压缩损失、重复错位叠采样、低分辨率或随机闪点 | 稳定远星、柔焦近尘、粒子淡入淡出，核对裁切后亮区仍有层次；画布像素预算随设备调整 |
| “不突出重点” | 关掉装饰，只看标题、证据、按钮的次序 | 第一次进入的人能指出主营业务及下一步；再恢复最有价值的效果 |

**桂小递星海的取舍**　保留仰望银河的广角构图。远处恒星提供尺度，中层亮带内部缓慢流动，少量近尘有连续轨迹、尺寸变化和局部遮挡。手指只拨动经过的区域，标定半径使用屏幕像素。先确认手机构图，再加运动，再加输入。实录包含无输入、有输入、移开三段。把景深需求写为“我希望看到近物跨过远物”，能避免反复把背景整体旋转。这个题材来自该公司的审美选择；其他项目从自己的业务内容重新立题。

**画布降级与成本**　控制绘制面积及分辨率，缓存尺寸、粒子贴图与重复渐变。持续慢帧可以逐步降分辨率。离屏、切后台与上下文丢失时停止无效绘制或退回静态。按设备比较画质与可操作性。抽查录屏首中末帧并同时验证图层已启动。

**同一幅画面有静态封面和动态纹理时**，检查预加载、CSS 裁切与渲染器实际选中的图片。手机竖屏切横屏，再趁横图下载时切回竖屏，检查最后显示的图、对齐位置和画布数。每次重新选图都使旧请求失效，包括切回已缓存图片的情况。新纹理可用时再显示动态层，失败时保留当前方向的静态画面。验收顺手再试局部触摸和纵向滚动。主动降低绘制频率后，用帧间隔和视觉表现检查卡顿，单看帧总数会误判。
